# 007-google-sign-in — Google 로그인

작성일: 2026-09-23  
상태: 코드·자동 검사 완료, 실제 계정 로그인 확인 전

## 목적과 범위

Supabase Auth의 Google 로그인으로 사용자를 구분합니다. 로그인하지 않아도 기존 사주 해석을 사용할 수 있습니다. 로그인은 결과를 계정에 저장하기 위한 선택 기능입니다. 배포는 이번 범위가 아닙니다.

## 사용 흐름

1. 화면 상단에 로그인 상태와 `Google로 로그인` 버튼을 보여줍니다.
2. 버튼을 누르면 Supabase가 Google 로그인으로 이동시킵니다. 사용자가 계정 선택과 동의를 직접 합니다.
3. 돌아온 뒤 로그인 상태를 보여줍니다. 로그아웃 버튼으로 세션을 끝낼 수 있습니다.
4. 취소·오류·설정 누락이면 이유를 쉬운 말로 알리고, 로그인 없이 해석을 계속 사용할 수 있습니다.

## 구현·보안 규칙

- 기존 Next.js 화면은 클라이언트에서 결과를 다룹니다. 첫 범위에서는 Supabase 브라우저 클라이언트로 OAuth와 계정 저장을 처리하며 서버 렌더링용 세션 쿠키는 추가하지 않습니다.
- `.env`의 `NEXT_PUBLIC_SUPABASE_URL`과 `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`만 브라우저에 노출합니다. 이 키는 공개 가능한 접속 식별값이며 비밀 관리자 키를 넣지 않습니다.
- 로그인 후 사용자 정보는 Supabase가 검증한 세션에서 가져옵니다. 이메일을 저장 표의 소유권 기준으로 사용하지 않고 고유 사용자 ID를 사용합니다.
- 로그인 전 브라우저에 있던 결과를 동의 없이 계정으로 자동 업로드하지 않습니다. 로그인·로그아웃 시 다른 계정의 결과를 화면에 남기지 않습니다.
- 화면 복귀 주소는 현재 사이트의 원점으로 고정합니다. Supabase의 허용된 Redirect URL에 `http://localhost:3000`을 등록해야 합니다. Google 제공 설정과 Google 측 콜백 설정도 필요합니다.
- 세션 토큰, Google 비밀값, 계정 ID를 작업일지·Git·Gemini 입력에 기록하지 않습니다.

## 완료 조건

- Google 로그인 시작, 성공 후 상태 표시, 로그아웃, 취소·오류 안내가 동작합니다.
- 로그인하지 않은 사용자도 해석할 수 있고, 별도 계정의 저장 결과가 서로 섞이지 않습니다.
- 키 또는 제공자 설정이 없어도 앱 전체가 멈추지 않고 설정 안내를 보여줍니다.
- 자동 테스트와 로컬 화면을 확인합니다. 실제 Google 계정 승인 단계는 참가자 직접 확인이 필요합니다.

## 구현·검증 기록

- Google 제공 기능이 해당 Supabase 프로젝트에서 켜져 있음을 공개 설정 응답으로 확인했습니다. `.env`의 프로젝트 URL과 공개 키가 준비된 것도 값 노출 없이 확인했습니다.
- 화면에 로그인 상태·Google 로그인·로그아웃·오류 안내를 추가했습니다. 인증 설정이 없어도 비로그인 해석 화면은 유지됩니다.
- 실제 Google 계정 선택·승인과 로그인 후 이 앱으로 돌아오는 동작은 아직 참가자 화면에서 확인하지 못했습니다.
- Supabase 대시보드의 URL 설정에서 기본 주소 `http://localhost:3000`과 허용된 복귀 주소 `http://localhost:3000/**`를 읽기 전용으로 확인했습니다. 실제 계정 복귀 동작은 별도입니다.
- `npm run check`: 타입 검사와 자동 테스트 62/62 통과. `npm run build` 통과. 로컬 화면에서 로그인 버튼·비로그인 해석·기존 브라우저 결과 복원을 확인했습니다. 참가자의 Google 계정 로그인은 아직 확인 전입니다.
