# 048-prepared-daily-fortune-palace-reveal — 오전 9시 사전 생성과 궁궐 문 열기

작성일: 2026-09-28
상태: 구현·Vercel·Supabase 연결 확인 완료, 기존 계정 표시 회귀 수정 진행 중

## 목표

각 로그인 사용자의 오늘의 운세를 한국 시간 매일 오전 9시에 미리 만들고 데이터베이스에 저장합니다. 사용자가 페이지에 들어오면 자기에게 저장된 오늘의 운세를 바로 읽습니다. 오늘의 운세 보기 버튼은 궁궐의 닫힌 문이며, 누르면 문이 열리면서 준비된 운세 카드가 나타납니다.

## 운세 기준

- 오늘의 운세는 **사용자의 생년월일과 태어난 시간으로 계산한 사주 차트**, 그리고 한국 날짜만 사용합니다.
- 관심 주제, 현재 상황, 원하는 방향, 기존 Gemini 해석 문장, 질문 답변과 연결하지 않습니다.
- 사주 차트 계산은 기존 `lib/saju`가 담당합니다. 오늘의 문장은 사주 차트와 날짜로 만든 정해진 규칙 기반의 가벼운 안내이며, Gemini를 사용자 수만큼 호출하지 않습니다.
- 사건·합격·수익·건강 결과를 예언하지 않고, 오늘 돌아볼 점과 작은 행동 하나만 제공합니다.

## 데이터 구조

### `user_saju_profiles` — 오늘의 운세 기준 정보

- `user_id`: 로그인 사용자 식별값. 사용자당 한 행입니다.
- `chart`: 사용자가 입력한 생년월일·태어난 시간으로 계산한 사주 차트입니다.
- `updated_at`: 기준 사주를 마지막으로 바꾼 시각입니다.

원본 생년월일·태어난 시간은 저장하지 않습니다. 이 표의 차트는 그 입력값으로 계산한 결과이므로, 오늘의 운세는 입력값에 의존하되 원본 개인정보를 다시 보관하지 않습니다. 사용자가 사주 입력을 완료하거나 기본 사주를 바꾸면 이 기준 정보를 갱신합니다.

오늘의 운세 기능보다 먼저 계정에 해석을 저장한 사용자는, 기존 `saju_results`에 있는 **계산된 사주 차트만** 기준표로 한 번 옮깁니다. 기존 해석 문장·관심 주제는 옮기거나 오늘 운세 생성에 사용하지 않습니다.

### `daily_fortunes` — 날짜별 미리 생성 운세

- `user_id`: 운세의 주인입니다.
- `fortune_date`: 한국 날짜(`YYYY-MM-DD`)입니다.
- `content`: 제목, 본문, 작은 행동, 재미용 색상·숫자를 담은 검증된 운세 데이터입니다.
- `created_at`: 생성 시각입니다.
- `source_profile_updated_at`: 어느 버전의 기본 사주 정보로 만들었는지 확인하는 시각입니다.

`user_id`와 `fortune_date`의 조합은 하나만 허용합니다. 같은 날짜의 Cron 재시도는 이미 성공한 행을 다시 만들거나 덮어쓰지 않습니다. 사용자가 기본 사주를 바꾼 경우에만 그 사용자·그 날짜 행을 새 기준으로 다시 생성합니다.

두 표 모두 행 단위 보안(RLS)을 적용합니다. 일반 사용자는 자기 행만 읽고 수정할 수 있으며, 다른 사용자의 프로필·오늘 운세는 읽을 수 없습니다.

## 예약 작업 흐름

```text
Vercel Cron (매일 09:00 KST, UTC 00:00)
  → GET /api/cron/daily-fortune
  → CRON_SECRET 인증
  → user_saju_profiles와 기존 saju_results에서 사용자별 계산 차트 조회
  → 각 사용자·한국 날짜의 daily_fortunes가 없으면 생성·저장
  → 생성 수·건너뜀 수·실패 수만 기록 (사주 내용·개인정보는 로그에 남기지 않음)
```

- `vercel.json`의 구현 예약식은 `0 0 * * *`입니다.
- Cron 경로는 `CRON_SECRET`이 있는 Vercel 요청만 실행합니다. 사용자 조회와 저장 권한을 위한 Supabase 서비스 역할 키는 Vercel 서버 환경변수에만 두고, 브라우저·코드·Git·작업일지에 저장하지 않습니다.
- 오류가 난 한 사용자는 다른 사용자 처리를 중단시키지 않고 실패 수로 기록합니다. 재시도 때 같은 날짜의 성공 행은 건너뜁니다.
- 초기 범위는 수업용 소규모 사용자 수를 전제로 합니다. 사용자 수가 함수 실행 시간에 비해 커지면, 다음 Spec에서 작업 대기열과 여러 묶음 처리를 추가합니다.

## 페이지 표시와 궁궐 문 연출

1. 로그인한 사용자가 페이지에 들어오면 자기의 `daily_fortunes`에서 표시 기준 날짜 행을 조회합니다. 한국 시간 00:00~08:59에는 전날 행을, 09:00부터는 당일 행을 사용합니다.
2. 저장된 운세가 있으면 접근할 때마다 닫힌 궁궐 문 버튼 `오늘의 운세 보기`를 보여줍니다. 누르면 문이 좌우로 열리고 준비된 운세 카드가 나타납니다. 이전 열림 기록은 브라우저에 저장하지 않습니다.
3. 표시 기준 날짜 행이 없으면 `오늘의 운세를 아직 준비하지 못했어요`와 다시 시도 안내를 표시합니다. 09시 전 전날 행 표시는 날짜를 바꾸어 당일 운세처럼 꾸미지 않습니다.
4. 새 사용자가 오전 9시 이후에 기본 사주를 처음 저장하면, 그 사용자 한 명의 오늘 운세를 서버에서 생성·저장한 뒤 바로 볼 수 있게 합니다. 다음 날부터는 Cron이 미리 생성합니다.

## 궁궐 문 연출과 접근성

- 버튼은 텍스트 `오늘의 운세 보기`와 닫힘·열림 상태를 함께 제공하고, 마우스·터치·키보드 Enter·Space로 동작합니다. 터치 영역은 최소 44px 이상입니다.
- 문 그림은 장식 요소로 처리하고, 운세가 열리면 화면 읽기 도구에 `오늘의 운세가 열렸습니다`를 알립니다. 키보드 초점은 보이는 운세 제목으로 이동합니다.
- 문은 250~400ms 안에 한 번만 열리고, 빠르게 다시 눌러도 최종 열린 상태가 됩니다. 문 연출은 결과 읽기와 다른 조작을 막지 않습니다.
- `prefers-reduced-motion`을 켠 사용자는 문 움직임 없이 운세 카드를 즉시 봅니다. 색만으로 상태를 표시하지 않습니다.
- 375px 너비와 가로 화면에서 문·카드가 넘치지 않고, 열린 뒤 키보드 초점이 가려지지 않아야 합니다.

## Vercel 시간 정확도

Vercel Cron은 UTC 시간대를 사용하므로 `0 0 * * *`는 한국 시간 오전 9시를 뜻합니다. Hobby 요금제는 하루 한 번 실행할 수 있지만 실제 호출이 최대 약 59분 늦을 수 있습니다. 따라서 Hobby에서는 `오전 9시대에 미리 생성`을 보장하며, **9시 정각**이 꼭 필요하면 Pro 이상의 분 단위 정밀도 또는 별도 예약 서비스를 사용합니다.

## 완료 조건

- 사용자별 기본 사주 차트가 관심 주제·기존 해석과 분리되어 저장된다.
- 오전 9시 Cron이 저장 프로필과 기존 저장 해석 계정에 오늘 한국 날짜 운세를 한 번씩 생성하고, 중복 호출에도 중복 행·불필요한 재생성이 없다.
- 로그인 사용자가 페이지에 들어오면 본인의 오늘 운세만 즉시 읽을 수 있고, 다른 사용자의 행은 접근할 수 없다.
- 저장 운세 없음·Cron 일부 실패·기본 사주 변경·오전 9시 이후 첫 저장을 정확히 처리한다.
- 궁궐 문 버튼의 마우스·키보드·터치, 빠른 연타, 모션 줄이기 설정, 375px 화면을 확인한다.
- 기존 로그인 사용자가 저장한 계산 차트만으로 기준표와 당일 운세를 준비하고, 첫 방문 뒤에도 색상·추천 숫자가 유지되는지 확인한다.
- 독립 테스트, 전체 하네스, 프로덕션 빌드, 실제 Vercel·Supabase 설정 확인을 완료한 뒤에만 완료로 표시한다.
