# 030-login-required-reading — 로그인 후 사주 해석

작성일: 2026-09-23  
상태: 구현·자동·로그아웃 화면 검증 완료, 실제 Google 로그인 후 생성 확인 전

## 목적

Google 로그인을 마친 사용자만 새 사주 해석을 만들고 자신의 저장 결과를 볼 수 있게 합니다. 화면 버튼뿐 아니라 서버의 해석 API에서도 Supabase가 확인한 로그인 토큰을 요구합니다.

## 사용 흐름

1. 로그아웃 상태에서는 입력 화면을 볼 수 있지만 해석 실행 버튼은 비활성화하고 `Google 로그인 후 해석할 수 있어요`라고 안내합니다.
2. 화면 위 계정 영역은 로그인이 해석에 필요하다는 이유와 `Google로 로그인` 행동을 함께 보여줍니다.
3. 로그인 뒤에는 기존 입력·해석·계정 저장 흐름을 사용합니다.
4. 로그아웃하면 계정 결과와 화면의 해석을 즉시 숨깁니다.
5. 과거 비로그인 브라우저 저장본은 임의로 삭제하지 않지만 더 이상 복원·표시·갱신하지 않습니다.

## 서버 인증 규칙

- 브라우저는 현재 Supabase 세션의 접근 토큰을 `Authorization: Bearer ...` 헤더로 해석 API에 보냅니다.
- 서버는 공개 가능한 Supabase 접속 키로 `/auth/v1/user`를 조회해 토큰을 검증한 뒤에만 입력 계산과 Gemini 호출을 진행합니다.
- 토큰 없음·형식 오류·만료·검증 실패는 HTTP 401과 로그인 안내로 끝냅니다. Gemini는 호출하지 않습니다.
- Supabase 설정 누락이나 인증 서비스 연결 실패는 HTTP 503으로 알리고 로그인 성공으로 간주하지 않습니다.
- 토큰·계정 ID·비밀값은 로그, 작업일지, Gemini 입력에 기록하지 않습니다.

## 완료 조건

- 로그아웃 화면에서 해석 버튼이 비활성화되고 로그인 방법이 보입니다.
- 버튼 상태를 우회해 API를 직접 호출해도 유효한 로그인이 없으면 해석되지 않습니다.
- 검증된 로그인 토큰이 있을 때 기존 해석 생성과 계정 저장 흐름이 유지됩니다.
- 로그아웃하면 결과가 숨겨지고, 과거 브라우저 저장본은 삭제되지 않습니다.
- 독립 인증 테스트, 전체 검사, 빌드, PC·모바일 화면을 확인합니다. 실제 Google 계정 선택·승인은 참가자가 직접 확인합니다.

## 검증 기록

- 독립 테스트에서 토큰 없음·잘못된 형식·Supabase 거절은 HTTP 401이며 Gemini를 호출하지 않는 것을 확인했습니다.
- Supabase가 확인한 사용자만 기존 Gemini 흐름으로 진행하고, 토큰·사용자 정보는 Gemini 자료에 들어가지 않는 것을 확인했습니다.
- Supabase 설정 누락과 인증 서비스 장애는 HTTP 503으로 끝나며 Gemini를 호출하지 않는 것을 확인했습니다.
- 화면은 로그인 이유와 행동을 함께 안내하고, 로그아웃 상태의 제출 버튼을 비활성화합니다. 세션 토큰은 API의 `Authorization` 헤더에만 보내며 로그아웃 시 결과를 숨깁니다.
- 과거 게스트 브라우저 저장값을 삭제하지 않으면서 복원·저장·갱신하지 않는 것을 검사했습니다.
- 사용자 제보 화면을 반영해 결과 영역의 최상위 조건을 `로그인 사용자 + 결과`로 강화했습니다. 로그아웃 이벤트도 비동기 계정 재확인 전에 사용자·결과·재시도 상태를 즉시 비웁니다.
- 로그인 관련 회귀 검사 2개를 추가했고, 전체 자동 검사 `144/144`와 배포용 빌드가 통과했습니다.
- 로컬 로그아웃 API 직접 호출은 HTTP 401과 로그인 안내를 반환했습니다. 기존 결과 상태가 남는 경우를 포함해 새로고침 전후 결과 영역이 보이지 않음을 확인했습니다. PC·375px 세로·812px 가로 화면에서 비활성 버튼과 안내를 확인했고 가로 넘침이 없었습니다.
- 실제 Google 계정 선택·복귀·로그인 후 해석 생성 및 계정 저장은 참가자 확인이 남았습니다. 외부 배포는 하지 않았습니다.
