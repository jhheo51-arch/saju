# 008-account-result-storage — 해석 결과를 계정에 저장

작성일: 2026-09-23  
상태: 코드·저장 표 적용·자동 검사 완료, 로그인 계정으로 실제 저장 확인 전

## 목적과 범위

로그인한 사용자의 검증된 사주 해석 **최근 1건**을 Supabase 데이터베이스에 보관합니다. 다른 기기에서도 같은 계정으로 로그인하면 그 한 건을 다시 볼 수 있게 합니다. 여러 결과 목록과 배포는 제외합니다.

## 사용 흐름

1. 비로그인 사용자는 지금처럼 이 브라우저의 최근 결과 1건을 임시 저장합니다.
2. 로그인 사용자는 해석 생성이 성공했을 때만 자신의 계정 결과 1건을 데이터베이스에 저장합니다. 새 결과는 이전 결과를 교체합니다.
3. 로그인하면 계정에 저장된 결과를 불러옵니다. 로그인 전 브라우저 결과는 자동 업로드하지 않습니다.
4. 저장·불러오기·삭제가 실패하면 실제 상태를 안내합니다. 저장 실패라도 방금 만든 해석은 화면에서 읽을 수 있고, 저장됐다고 말하지 않습니다.
5. 로그아웃하거나 계정이 바뀌면 해당 계정 결과를 화면에서 지웁니다.

## 데이터 계약

- `public.saju_results`: `user_id uuid` 기본키 및 `auth.users(id)` 참조, `created_at timestamptz`, `chart jsonb`, `topic text`, `reading jsonb`.
- 저장 대상은 계산된 사주 원자료와 검증된 생성 문장, 주제, 생성 시각입니다. 원본 생년월일·출생시간, 질문 원문, Gemini API 키, Google 토큰은 저장하지 않습니다. 계산값·결과 문장도 개인에 관한 자료로 취급합니다.
- 브라우저에 표시하기 전 계정에서 읽은 데이터도 기존 저장 형식 검증을 거칩니다. 손상된 결과는 표시하지 않고 오류를 알립니다.
- 사용자 소유권은 `auth.uid() = user_id`로 검사하는 행 단위 보안(RLS)을 적용합니다. 익명 역할의 표 접근 권한을 제거하고, 로그인한 사용자에게 자기 행의 조회·추가·수정·삭제만 허용합니다. 관리자 비밀키는 앱에서 사용하지 않습니다.

## 오류와 경계

- 로그인 만료 또는 저장 표 미설치 시 원인을 구분해 안내하고, 허위 저장 성공 메시지를 보이지 않습니다.
- 해석 실패는 기존 계정 결과를 교체하지 않습니다.
- 기존 브라우저 결과는 삭제하거나 계정으로 자동 이전하지 않습니다. 이번 범위에서 수동 가져오기 기능도 제외합니다.
- 공유 컴퓨터에서는 비로그인 상태의 브라우저 임시 결과가 남을 수 있으므로 삭제 버튼과 안내를 유지합니다.
- 계정 삭제·전체 데이터 내보내기·결과 목록은 별도 범위입니다.

## 완료 조건

- DB 마이그레이션(표 구조 변경 파일)이 작성되고 RLS의 본인/타인/비로그인 접근을 검증합니다.
- 로그인 사용자 생성→저장→재접속 후 복원→교체→삭제가 동작합니다.
- 비로그인 기존 흐름, Gemini 오류, 저장 실패, 오래된 오늘의 운세 안내가 유지됩니다.
- 자동 테스트와 로컬 화면을 확인합니다. 실제 데이터베이스 반영 및 계정 간 접근 검증을 하지 못하면 완료로 표시하지 않습니다.

## 구현·검증 기록

> 후속 변경: `030-login-required-reading.md`부터 비로그인 저장·복원은 중단합니다. 기존 브라우저 저장값은 삭제하지 않지만 화면에 표시하거나 계정으로 자동 이전하지 않습니다. 아래 내용은 당시 구현 기록으로 보존합니다.

- `supabase/migrations/20260923000100_create_saju_results.sql`을 작성하고 지정한 Supabase 프로젝트에 동일한 SQL을 적용했습니다. SQL 편집기에서 성공을 확인했습니다.
- 실제 표에서 `relrowsecurity=true`, 비로그인 조회 권한 `false`, 로그인 조회 권한 `true`, 본인 행 전용 정책 4개를 확인했습니다. 공개 키만 쓴 비로그인 REST 조회는 HTTP 401이었습니다.
- 계정 결과 조회·교체 저장·삭제와 형식 검사, 비로그인 브라우저 저장 유지를 구현했습니다. 자동 검사는 별도 결과를 기록합니다.
- 아직 실제 Google 계정으로 생성→저장→재로그인 복원·삭제와 서로 다른 두 계정의 차단을 확인하지 못했습니다. 따라서 이 Spec은 완료로 표시하지 않습니다.
- 독립 테스트 작성자가 저장·조회·삭제, 잘못된 형식 거절, 비로그인 흐름, 마이그레이션의 권한 계약을 검사했습니다. 최종 `npm run check`: 62/62 통과, `npm run build`: 통과. 실제 로그인 계정으로 데이터를 넣어보는 시험은 남았습니다.
