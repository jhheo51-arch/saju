# 005-gemini-interpretation — Gemini 사주 해석과 임시 결과 저장

작성일: 2026-09-23  
상태: 구현·자동 검증 완료, 참가자 사용 확인 전

## 목표

기존 사주 계산 결과를 바탕으로 성향 카드, 선택한 주제의 풀이, 오늘의 운세를 쉽고 가볍게 생성합니다. 성공한 결과는 우선 현재 브라우저의 `localStorage`에 저장하여 다시 열어볼 수 있게 합니다. 로그인과 서버 저장은 이후 단계입니다.

## 사용 흐름

1. 사용자가 양력 생년월일, 정확한 출생시간, 연애·일·돈 중 하나를 입력하고, 원하면 ‘요즘 궁금한 점’을 200자 이내로 적습니다.
2. 기존 `lib/saju`가 사주를 계산합니다. Gemini는 계산값을 변경하거나 대신 계산하지 않고, 계산 결과를 쉬운 문장으로 풀어 쓰는 역할만 합니다.
3. 해석 요청 중에는 진행 상태를 보여주고 중복 요청을 막습니다.
4. 성공하면 **성향 카드 → 선택 주제 풀이 → 오늘의 운세** 순서로 표시합니다. 질문이 있으면 주제 풀이에 반영하고, 없으면 일반적인 풀이를 보여줍니다.
5. 유효한 결과만 브라우저에 저장합니다. 사용자는 저장된 결과를 다시 볼 수 있고 삭제할 수 있습니다.

## Gemini 연결 계약

- 사용할 모델 식별자: `gemini-3.5-flash-lite`. 구현 시 해당 프로젝트의 API 접근 가능 여부를 확인합니다. 접근 불가 시 다른 모델로 조용히 바꾸지 않고 오류를 알립니다.
- API 키는 서버의 `GEMINI_API_KEY` 설정값으로만 읽습니다. 브라우저 코드, 응답, `localStorage`, Git 기록에 넣지 않습니다. 키를 채팅이나 문서에 붙여 넣도록 요청하지 않습니다.
- 브라우저는 입력값을 우리 서버에 보냅니다. 서버가 입력을 재검증하고 `lib/saju`로 다시 계산한 뒤, Gemini에는 해석에 필요한 계산 결과·주제·선택 질문·한국 날짜만 전달합니다. 원본 생년월일과 출생시간은 Gemini에 보내지 않습니다.
- Gemini 응답은 구조화된 데이터로 요청하되, 서버에서 필수 항목·길이·날짜·주제 일치 여부를 다시 검사합니다. 모델이 돌려준 HTML은 사용하지 않고 일반 텍스트로 표시합니다.
- 한 요청의 결과 데이터는 `personality`(제목·설명), `topic`(주제·제목·설명), `today`(한국 날짜·제목·설명) 세 부분으로 구성합니다. 화면에는 어떤 계산 정보와 주제를 해석에 사용했는지 간결하게 확인할 수 있게 합니다.
- 날짜 기준은 `Asia/Seoul`의 요청 날짜입니다. 저장된 예전 ‘오늘의 운세’를 새 날짜의 운세로 표시하지 않습니다.

## 해석 문장 규칙

- 사주를 처음 접하는 20~30대가 읽을 수 있도록 짧고 친근한 한국어로 씁니다. 전통적 해석에 바탕을 둔 재미·자기성찰 콘텐츠임을 알리고 성격, 미래 사건, 건강, 재산을 확정하거나 겁주지 않습니다.
- 성향 카드는 계산된 네 기둥·일간·오행을 바탕으로 하되, 오행 글자 수만으로 사람의 우열이나 성격 강약을 판단하지 않습니다.
- 주제별로 연애는 관계·대화, 일은 협업·일하는 방식, 돈은 소비·계획 습관을 다룹니다. 돈 풀이에서 투자·수익을 보장하지 않습니다.
- 질문은 선택한 주제와 관련된 맥락으로만 사용합니다. 질문에 포함된 지시문이 해석 규칙이나 서버 동작을 바꾸지 못하도록 사용자 입력과 생성 지시를 분리합니다.
- 전문 용어를 쓸 때는 승인된 용어 설명이 있는 단어만 쓰고 화면에서 누르거나 키보드로 선택해 ‘상징하는 뜻 → 쉬운 비유 또는 예’ 설명을 볼 수 있게 합니다. 설명이 준비되지 않은 용어는 일반적인 말로 바꿉니다. 모델이 만든 뜻 설명을 검증 없이 사전에 추가하지 않습니다.

## 브라우저 저장 규칙

- `localStorage`는 현재 브라우저·주소에만 적용되는 임시 보관입니다. 로그인이나 기기 간 동기화, 영구 백업으로 설명하지 않습니다. 브라우저 데이터를 지우면 결과가 없어질 수 있습니다.
- 저장 대상은 **검증을 통과한 생성 결과와 표시·구분에 필요한 최소 정보**입니다. API 키, 원본 생년월일·출생시간, 자유 질문 원문은 저장하지 않습니다. 결과 문장에 개인 정보나 질문 원문이 불필요하게 반복되지 않도록 합니다.
- 저장 형식에는 버전 번호와 생성 시각, 한국 날짜, 선택 주제를 포함합니다. 형식이 오래되거나 손상된 데이터는 화면을 멈추게 하지 않고 무시하며 삭제할 수 있게 합니다.
- 생성에는 성공했지만 브라우저 저장에 실패하면 결과는 현재 화면에 보여주고 ‘저장되지 않았음’을 알립니다. 해석 요청이 실패하면 새 결과를 저장하지 않고 이전에 저장된 유효한 결과는 그대로 둡니다.
- **확정:** 사용자가 최근 결과 한 건만 보관하기로 선택했습니다. 새로 성공한 결과는 이전 저장본을 교체하고, 삭제 버튼은 이 한 건을 지웁니다.

## 오류와 재시도

- 날짜·시간·주제·질문 길이가 잘못되면 무엇을 고칠지 알려주고 Gemini 요청을 하지 않습니다.
- API 키 누락, 모델 접근 불가, 네트워크·한도 오류, 응답 형식 오류는 각각 안전한 안내를 보여줍니다. 키나 내부 오류 세부 내용을 화면에 노출하지 않습니다.
- 오류 시 가짜 해석을 대신 표시하지 않습니다. 입력을 유지하고 재시도할 수 있게 합니다. 재시도는 새 요청이며 자동 무한 반복하지 않습니다.
- 외부 API 호출에는 사용량·비용이 발생할 수 있으므로 중복 클릭 방지와 적절한 요청 제한을 구현 단계에서 확인합니다.

## 완료 조건 및 검증 계획

- 정상 입력·세 주제·질문 있음/없음에서 서로 맞는 세 결과 영역이 생성됩니다.
- 같은 사주 계산값은 Gemini 응답 전후에 바뀌지 않고, 원본 생년월일·시간 및 API 키가 Gemini 요청이나 브라우저 저장 데이터에 들어가지 않습니다.
- 전문 용어는 모두 클릭·키보드로 뜻을 볼 수 있거나 쉬운 말로 대체됩니다. 좁은 화면에서도 읽을 수 있습니다.
- 성공 결과의 저장·다시 보기·삭제, 새 날짜의 오늘 운세 구분, 저장 불가 상황을 확인합니다.
- 입력 오류, 키 누락, API 실패, 비정상 응답에서 가짜 풀이 없이 안전한 오류와 재시도가 작동합니다.
- 자동 검사와 `localhost` 브라우저 확인 후에도 참가자의 실제 사용 확인은 별도로 받습니다. 이 문서 작성만으로 구현·검증 완료로 표시하지 않습니다.

## 구현·검증 기록

- 2026-09-23: Next.js 서버 경로 `app/api/interpret/route.ts`에서 `gemini-3.5-flash-lite`를 호출합니다. 서버가 입력을 검증하고 사주를 다시 계산하며, Gemini에는 계산값·주제·선택 질문·한국 날짜만 보냅니다. 요청에는 `store: false`를 지정했습니다.
- 브라우저 화면에 생성 중·성공·오류·재시도 상태와 최근 결과 한 건 저장·다시 열기·삭제 기능을 연결했습니다. API 키는 코드와 브라우저 저장 결과에 넣지 않았습니다. 해석 속 등록된 사주 용어는 눌러 뜻을 볼 수 있습니다.
- 독립 테스트 작성자가 서버 요청·오류·응답 형식, 원본 생년월일·시간 제외, 저장·삭제, 오행 용어 설명 검사를 보강했습니다. `npm run check`: 타입 검사와 자동 테스트 42/42 통과. `npm run build`: 통과. 배포는 하지 않았습니다.
- 임의의 테스트 날짜(2000-01-01, 12:00)로 실제 Gemini 연결 성공과 세 영역의 응답을 확인했습니다. 첫 응답에서 흙 기운을 나무에 비유한 오류를 발견해 모델 지침과 용어 설명을 보강했습니다. 재호출 결과에서 흙·산 비유로 수정된 것을 확인했습니다. 생성 문장의 의미 정확성을 자동으로 완전히 보장하지는 않습니다.
- `http://localhost:3000/`에서 생성 중 표시, 실제 해석 세 카드, `무토` 클릭 설명, 새로고침 후 최근 해석 복원, 1990년 이전 날짜의 입력 오류를 확인했습니다. 별도 임시 로컬 서버에는 가짜 키를 넣어 연결 오류 안내와 재시도 버튼을 확인하고 버튼을 눌렀습니다. 실제 키·설정은 변경하지 않고 임시 서버와 탭은 종료했습니다. 참가자의 직접 사용 확인은 아직입니다.
