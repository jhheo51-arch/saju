# 📋 기획서 (PRD) : 나만의 사주 서비스

> 사주를 처음 보는 사람도 자기 이야기를 쉽고 가볍게 읽을 수 있는 웹 서비스입니다.

작성일: 2026-09-23

작성자: 참가자 (서비스 기획)

---

## 1. 풀고자 하는 문제

- **지금은 이렇게 해요:** 사주 결과를 보려면 생년월일과 시간을 입력하고 낯선 용어가 많은 풀이를 읽습니다.
- **이게 불편해요:** 용어가 어렵고 설명이 나와 연결되지 않거나 지나치게 진지하게 느껴집니다.
- **이렇게 되면 좋겠어요:** 사주 계산을 바탕으로 내 성향과 관심 주제를 쉬운 말, 가벼운 분위기의 맞춤 문장으로 읽을 수 있습니다.

## 2. 사용자

- **누가 쓰나요?** 사주를 처음 접하는 20~30대. 친구·연인과 재미로 이야기할 소재를 찾는 사람도 포함합니다.
- **언제 쓰나요?** 자기 성향이 궁금할 때, 연애·일·재물·인간관계·가족·공부·진로·취미·건강 중 관심사가 생겼을 때, 오늘이나 이번 주의 가벼운 운세가 궁금할 때.
- **어디서 쓰나요?** 휴대전화와 컴퓨터의 웹 브라우저.

## 3. 입력 자료

- **입력 내용:** 양력 생년월일, 출생시간, 선택한 주제 1개(연애·일·재물·인간관계·가족·공부·진로·취미·건강). 오늘의 운세에는 한국 날짜를, 이번 주 운세에는 한국 시간 기준 월요일~일요일을 사용합니다. ‘요즘 궁금한 점’ 자유 입력은 제거했습니다.
- **반드시 필요한 항목:** 현재 계산 엔진 기준으로 양력 생년월일과 정확한 출생시간. 출생시간을 모를 때의 지원 방식은 미정입니다.
- **개인정보:** 생년월일·출생시간은 개인에 관한 내용입니다. 비로그인 사용자의 최근 결과 1건은 이 브라우저의 `localStorage`에 임시 저장하고, Google 로그인 사용자는 자신의 Supabase 계정에 최근 결과 1건을 저장합니다. 저장에는 원본 생년월일·출생시간을 넣지 않습니다. Gemini에는 원본 생년월일·시간 대신 계산 결과만 전달합니다. 이전 버전의 저장 결과는 임의로 삭제하지 않습니다.
- **현재 코드의 제한:** 1990-01-01 이후 양력 날짜와 정확한 출생시간만 받습니다. 이 제한을 넓힐지는 별도로 결정합니다.

## 4. 목표 서비스의 핵심 경험과 개인화 규칙

1. 생년월일과 출생시간을 입력하면 기존 `lib/saju`가 사주를 계산합니다. 계산은 설명 생성 도구에 맡기지 않습니다.
2. 계산된 **일간·월주·오행 글자 수**를 먼저 짧게 보여주고, **02 쉬운 성향·선택 주제 풀이 → 03 나의 아바타 → 04 오늘·이번 주 운세** 순서로 구성합니다. 큰 오행 8칸 그래프는 제거합니다.
3. 성향 풀이에는 해당 사람의 일간, 주제별 풀이에는 월주가 실제 이름으로 등장해야 합니다. 전통적 상징이 일상 행동과 어떻게 연결되는지 예로 설명하되, 사주가 성격이나 미래를 확정한다는 식으로 말하지 않습니다.
   실제 이름만 끼워 넣는 설명은 부족합니다. 계산된 근거 두 가지 이상을 연결해 쉬운 뜻, 선택 주제에 맞는 일상 장면, 균형 있게 볼 점, 시도해 볼 작은 행동까지 이어지는 풀이를 목표로 합니다. 새 결과는 이 다섯 항목을 구분해 보여주고, 이전 저장 결과는 기존 한 문단 형태로 유지합니다. 자세한 기준은 `docs/specs/017-personalized-reading-prompt.md`와 `docs/specs/021-structured-reading-sections.md`에 기록합니다.
4. 설명은 중학생도 읽을 수 있는 짧고 친근한 문장으로 쓰고, 낯선 사주 용어가 나오면 바로 뜻을 풀어줍니다. 추상적인 말만 반복하지 않고 일상적인 행동 예시를 한 가지 제시합니다.
5. 편관·비견·편인·정인·식신, 천간·지지처럼 처음 보는 용어는 원래 이름을 남깁니다. 별도 용어 사전 영역을 두지 않고, 결과에 등장한 단어를 누르면 그 자리에서 쉬운 뜻을 볼 수 있게 합니다. 실제 계산되지 않은 십성을 개인별 결과처럼 표시하지 않습니다.
6. 클릭한 설명은 단어가 화면의 어디에 적히는지가 아니라 사주에서 무엇을 상징하는지부터 알려줍니다. 예를 들어 천간은 전통적으로 하늘의 기운을 나타내는 이름이라는 뜻과 자연물 비유를 먼저 설명합니다.
7. 이 원칙은 **화면에 표시하는 모든 사주 전문 용어**에 적용합니다. 계산 원자료뿐 아니라 이후 성향 카드·주제별 풀이·오늘·이번 주 운세에 등장하는 용어도 누르거나 키보드로 선택하면 뜻, 쉬운 비유 또는 예시를 볼 수 있어야 합니다. 독립된 긴 용어 사전 영역은 만들지 않습니다. 설명이 준비되지 않은 전문 용어는 뜻을 먼저 작성하거나 쉬운 말로 바꾼 뒤 표시합니다. 설명은 전통적 해석임을 분명히 하고 개인의 성격·미래를 단정하지 않습니다.

**개인화 규칙**

| 규칙 | 사용할 정보 | 결과에 반영할 방식 |
|---|---|---|
| 성향 카드 | 계산된 사주의 네 기둥, 일간(태어난 날을 대표하는 글자), 오행의 분포 | 한 줄 요약과 짧은 설명으로 풀고, 사용한 용어의 뜻을 바로 알려줍니다. 성격을 확정하지 않습니다. |
| 주제별 풀이 | 같은 계산 결과 + 선택한 주제 | 연애는 마음 표현, 일은 협업, 재물은 소비 계획, 인간관계·가족은 각 관계의 소통, 공부는 학습 습관, 진로는 분야 탐색, 취미는 즐거움, 건강은 휴식과 생활 리듬에 초점을 맞춥니다. 질병·치료 결과나 특정 사건·수익을 예측하지 않습니다. |
| 계산 근거 | 일간·월주·여덟 글자의 오행 개수 | 결과 위에 실제 계산값을 보여주고, 성향·주제 풀이에 해당 이름을 명시합니다. 단, 이것만으로 강약이나 운명을 단정하지 않습니다. |
| 오행 글자 수 | 계산된 목·화·토·금·수의 글자 수 | 02의 계산 근거에 간단한 숫자만 남깁니다. 기존 8칸 그래프는 제거하고, 숫자로 성격·미래를 판단하지 않습니다. |
| 오행 궁궐 아바타 | 계산된 일간·월주·오행 | 목·화·토·금·수 다섯 단순 한지 인형풍 궁인 중 하나를 결과의 `03` 영역에 표시합니다. 같은 그림에도 사주 글자 조합에 따라 왕실·관리·군인·내시·궁녀·의학 분야의 다른 역할을 붙이고, 궁궐 역할·맡은 일·함께할 기운 세 가지를 보여줍니다. 모두 실제 신분·성별·궁합을 뜻하지 않는 창작 설정임을 적습니다. 복잡한 풍경 대신 단순한 해·언덕 배경을 사용하고 원본 그림은 보존합니다. |
| 오늘·이번 주 운세 | 계산 결과 + 한국 기준 오늘 날짜와 월~일 기간 | 오늘과 이번 주에 생각해 볼 점, 작은 행동 제안을 각각 하나씩 제시합니다. 미래 사건을 단정하지 않습니다. |
| 말투와 근거 | 위 정보 전체 | 친구처럼 쉽게 말하고 겁주는 표현을 피합니다. 현재 코드의 오행 숫자는 여덟 글자의 개수이므로 이것만으로 성격의 강약이나 운명을 판단하지 않습니다. |

- **완료된 프로토타입에서 AI에게 맡긴 것:** 없음. 위 화면 구조와 문장 규칙만 확인했습니다.
- **현재 AI에게 맡긴 것:** `gemini-3.5-flash-lite`가 기존 사주 계산 결과를 받아 위 규칙에 맞는 설명 문장만 만듭니다. 계산 자체는 기존 코드가 수행합니다. 연결·저장 방식과 확인 결과는 `docs/specs/005-gemini-interpretation.md`에 기록했습니다.
- **사람이 확인할 것:** 풀이가 계산된 일간·월주와 선택 주제에 맞는지, 어려운 용어를 풀었는지, 무섭거나 단정적인 표현이 없는지 검토합니다.

## 5. 결과와 완료 조건

- **첫 프로토타입 결과물:** 기존 웹앱에서 날짜·시간·주제와 세 결과 영역의 구조를 확인했습니다. 이후 Gemini 해석 문장 표시를 추가했습니다. 질문 입력은 이전 버전에만 있었습니다.
- **용어 설명 완료 조건:** 실제 화면에 등장한 사주 전문 용어는 모두 눌러 뜻을 확인할 수 있습니다. 설명은 위치나 글자 수만 말하지 않고 ‘무엇을 상징하는지 → 쉬운 예’ 순서로 알려줍니다. 마우스와 키보드로 열고 닫을 수 있고, 화면을 긴 사전 목록으로 채우지 않습니다. 현재 프로토타입에서 연결된 용어는 천간·지지이며, 다른 용어는 실제 결과에 등장할 때 같은 규칙을 적용합니다.
- **정상 상황:** 지원되는 생년월일·시간을 입력하면 계산 근거와 성향 카드, 선택 주제 풀이, 아바타, 오늘·이번 주 운세가 순서대로 보입니다.
- **향후 구현의 오류 상황:** 날짜·시간이 비었거나 잘못되면 수정할 항목을 알려줍니다. 향후 AI 응답이 실패하거나 형식이 틀리면 재시도를 안내하고 가짜 풀이를 보여주지 않습니다.
- **향후 화면 확인:** 휴대전화에서도 읽기 쉽고, 정상·입력 오류·AI 오류를 실제 화면에서 확인합니다.

## 6. 나중에 추가할 것 / 제외할 것

- **현재 단계:** 비로그인 사용자는 최근 결과 1건을 현재 브라우저에 임시 저장합니다. Google 로그인 사용자는 최근 결과 1건을 계정에 저장해 다른 기기에서 다시 볼 수 있도록 합니다. 로그인 전 브라우저 결과는 계정에 자동으로 올리지 않습니다.
- **이번 로그인·저장 기능의 확인:** 구현과 데이터베이스 보안 설정은 진행했으며, 실제 Google 계정 로그인과 계정 간 결과 분리는 사용 확인이 남아 있습니다. 세부 범위는 `docs/specs/007-google-sign-in.md`, `008-account-result-storage.md`를 따릅니다.
- **후속 기능:** 친구·연인 궁합.
- **서비스 범위에서 제외:** 결제와 전문가 상담 연결.

## 7. 만드는 방식과 공유 방법

화면 색상은 참가자의 최신 요청에 따라 기존의 차분한 청록·적갈·금색 테마를 유지합니다. 별도로 제안했던 밝은 궁궐 팔레트와 궁서체 변경은 모두 취소했습니다.

- [ ] 일회성
- [ ] 자동화
- [x] 도구·웹

선택: 기존 **Next.js 웹앱**에서 사주 계산은 `lib/saju`를 재사용하고, Gemini API 키는 서버에서만 사용합니다. Google 로그인과 계정 저장은 Supabase를 사용합니다. 공개 배포는 아직 하지 않았습니다.

공유·확인: 개발 서버가 켜진 동안 이 컴퓨터의 [http://localhost:3000/](http://localhost:3000/)에서 화면을 확인합니다. `localhost`는 현재 컴퓨터에서 열어보는 주소이지 다른 사람에게 공유할 공개 주소가 아닙니다. **아직 배포하지 않습니다.** 성향 카드·주제별 풀이·오늘의 운세 등 핵심 기능을 어느 정도 구현하고 직접 확인한 뒤 배포 시점, 공개 범위, 개인정보 처리 방식을 별도로 정합니다.

## 8. 첫 프로토타입에서 완성을 목표로 한 것

이번 작업의 목표는 **입력→기존 사주 계산→성향 카드·주제 풀이·오늘의 운세 자리 확인**까지 이어지는 화면 프로토타입입니다. 로그인, 결과 저장, 실제 사주 해석, LLM API 연결과 배포는 다음 단계에서 다룹니다.

## 9. 첫 구현 목표 (30분 예산)

기존 계산 화면에 주제와 선택 질문을 추가하고, 정상 입력 뒤 세 가지 결과 영역과 원래 계산된 사주를 보여줍니다. 각 영역은 해석 준비 중임을 분명히 표시합니다.

## 10. 테스트 사례

| 번호 | 입력 상황 | 기대 결과 | 위험도 |
|---|---|---|---|
| 1 | 지원되는 생년월일·출생시간, 연애 주제, “요즘 궁금한 점”을 입력 | 계산 결과와 성향·연애·오늘의 운세 자리 및 입력한 질문이 표시됨. 해석 문장은 없음 | 보통 |
| 2 | 재물 주제를 선택 | 질문 없이 계산되며 재물 풀이 자리가 표시됨 | 보통 |
| 3 | 출생시간을 비우거나 존재하지 않는 날짜를 입력 | 필요한 입력을 알려주고 결과를 표시하지 않음 | 높음 |
| 4 | 결과에 표시된 사주 전문 용어를 클릭하거나 키보드로 선택 | 별도 사전 페이지 없이 해당 용어의 뜻과 쉬운 예가 열리고 다시 닫힘. 위치 설명만 나오지 않음 | 높음 |
