# 사주 답변 검사

사주를 새로 계산하지 말고 서비스가 제공한 계산 결과를 기준으로 답변 품질을 검사합니다. 생년월일이나 출생시간이 없다는 이유로 값을 추측하지 않습니다.

## 검사 대상을 먼저 구분합니다

- 실제 답변과 계산 근거가 있으면 `scripts/check_answer.py`로 결정 가능한 항목을 먼저 검사합니다.
- 프롬프트·API·파서·저장 코드의 설계를 검토할 때는 [검토 기준](references/review-rubric.md)을 읽고 데이터가 계산부터 출력까지 어떻게 이어지는지 확인합니다.
- 필요한 계산 근거나 맥락이 없으면 해당 항목을 `NOT TESTED`로 남깁니다. 그럴듯한 근거를 만들어 통과시키지 않습니다.

## 실제 답변 검사

검사 입력은 다음 구조의 JSON입니다.

```json
{
  "chart": {
    "dayMaster": "신금",
    "monthPillar": "무자(토·수)",
    "yinYang": "음 4·양 4",
    "season": "겨울(자월)"
  },
  "context": {
    "topic": "연애",
    "currentSituation": "새로운 만남을 시작하고 싶음",
    "desiredDirection": "반복되는 모습을 알고 싶음"
  },
  "response": {
    "basis": "신금, 무자(토·수), 음 4·양 4, 겨울(자월)",
    "answer": "...",
    "action": "..."
  }
}
```

파일을 받았으면 다음처럼 실행합니다.

```bash
python .agents/skills/saju-answer-reviewer/scripts/check_answer.py answer.json
```

스크립트의 `FAIL`은 정확한 근거 한 줄 불일치, 260~800자·세 문단 구조 위반, 금지된 일반론, 관계 답변의 행동 기준 세 가지 부족처럼 기계적으로 확인 가능한 실패입니다. 맥락이 없으면 `NOT TESTED`와 종료코드 `3`을 반환합니다. `WARN`은 현재 상황이나 원하는 방향이 답변에 그대로 드러나지 않아 의미 검토가 필요한 경우입니다.

대표 사례 전체를 한 번에 검사할 때는 프로젝트 루트에서 `npm run eval:saju`를 실행합니다. 타입 검사와 제품 테스트까지 함께 확인하려면 `npm run harness`를 사용합니다.

## 결과 보고

다음 내용을 짧고 구체적으로 보고합니다.

1. 전체 판정: `PASS`, `FAIL`, `NOT TESTED`
2. 사용한 계산 근거와 맥락
3. 실패·주의 항목별 실제 문장 또는 코드 위치
4. 각 문제를 고칠 수 있는 최소 수정안
5. 자동 검사와 사람이 판단한 항목의 구분

사용자가 고쳐 달라고 요청하지 않았다면 검토만 하고 제품 코드나 답변을 변경하지 않습니다. 답변을 고칠 때도 계산값을 새로 만들거나 특정 오행·띠·성별을 운명처럼 단정하지 않습니다.

생년월일·출생시간·로그인 토큰 등 원본 개인정보는 검사 보고서에 반복해서 적지 않습니다. 사주 해석은 확정적 사실이나 의학·법률·재무 판단이 아니라 자기 성찰을 돕는 참고 표현으로 다룹니다.
