# 사주 답변 검토 기준

실제 답변의 의미를 검토하거나 프롬프트·API·파서·저장 흐름을 점검할 때 사용합니다. 자동 검사 결과만으로 확인할 수 없는 항목을 중심으로 봅니다.

## 판정

- `PASS`: 필요한 근거를 실제 계산값에서 가져왔고, 질문과 맥락에 답하며, 위험한 단정이 없습니다.
- `FAIL`: 다른 사주의 근거를 쓰거나 근거 없이 단정하고, 질문을 회피하거나, 예언·차별·민감정보 노출 위험이 있습니다.
- `NOT TESTED`: 계산 결과, 사용자 맥락, 실제 응답처럼 판정에 필요한 자료가 없습니다.

## 필수 검토 항목

### 1. 계산 근거

- 계산은 `lib/saju` 같은 결정적 코드가 맡고 생성 모델이 생년월일로 다시 계산하지 않아야 합니다.
- 답변에 표시한 일간·월주·음양·계절은 제공된 계산값과 정확히 일치해야 합니다.
- 후속 질문의 근거는 `일간 · 월주 · 음양 · 계절` 네 계산값만 한 줄로 적고 설명을 덧붙이지 않습니다.
- 여덟 글자의 단순 오행 개수만으로 성격 강약, 용신, 특정 인연을 확정하지 않습니다.

### 2. 질문과 개인 맥락

- 첫 문단부터 사용자의 실제 질문에 직접 답해야 합니다.
- 현재 상황과 원하는 방향을 단순 반복하지 말고, 계산 근거가 그 상황에서 어떤 관찰점으로 이어지는지 설명해야 합니다.
- 이름만 바꾸면 누구에게나 적용되는 답변은 실패입니다.

### 3. 관계 답변

- `부족한 부분을 채워주는 사람`, `좋은 기운을 가진 사람`, `귀인 같은 사람`으로 끝내지 않습니다.
- 대화 속도, 감정 표현, 갈등 뒤 회복, 경계 존중, 결정 방식 중 최소 세 가지를 사용자가 실제로 살펴볼 행동으로 제시합니다.
- 오행 수가 적다는 이유만으로 상대의 오행·띠·성별을 지정하지 않습니다.

### 4. 예언과 위해 방지

- 합격, 연애 성사, 결혼, 수익, 질병 또는 정확한 시점을 확정하지 않습니다.
- 불안을 키우거나 겁주는 표현, 사람의 가치를 낮추는 표현, 치료·투자·법률 결정을 대신하는 표현을 실패로 봅니다.
- 불확실성을 숨기지 않고 자기 성찰과 선택을 돕는 참고 문장으로 씁니다.

### 5. 작은 행동

- 지금 실행할 수 있고 결과를 관찰할 수 있는 한 가지 행동이어야 합니다.
- `긍정적으로 생각하세요`, `좋은 사람을 만나세요`처럼 측정할 수 없는 조언은 부족합니다.
- 답변의 근거와 질문에 연결되지 않은 행동을 덧붙이지 않습니다.

### 6. 개인정보와 저장

- 생성 모델에는 필요한 계산 결과와 질문 맥락만 전달하고, 원본 생년월일·출생시간·인증 토큰·API 키는 전달하지 않습니다.
- 질문 원문과 답변의 저장 범위는 서비스 명세와 일치해야 합니다.
- 로그와 오류 메시지에 민감정보를 그대로 남기지 않습니다.

## 코드 검토 시 확인할 흐름

`입력 검증 → 결정적 사주 계산 → 모델에 전달할 최소 맥락 → 구조화 응답 파싱 → 계산 근거 대조 → 화면 표시 → 명세에 맞는 저장` 순서로 추적합니다. 한 단계의 실패를 가짜 기본 답변으로 바꾸지 말고 사용자에게 재시도 가능한 오류로 보여야 합니다.
